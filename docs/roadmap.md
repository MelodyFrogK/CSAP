# 로드맵 — CSAP 자동화 서비스 확장 계획

CSAP 신청 패키지는 보통 다음으로 구성됩니다.

1. **클라우드컴퓨팅서비스 보안운영 명세서** ← **1단계(현재 구현 완료)**
2. **사후 서면평가 증적자료 제출목록** ← 2단계(계획)
3. **신청양식**(신청서 등) ← 3단계(계획)

세 산출물 모두 **동일한 기업 입력 문서(PDF/Word/…)** 에서 파생되므로, 문서 추출·청크·
근거 검색 파이프라인(`app/core`)과 LLM 공급자 추상화(`app/llm`)를 공유하도록 설계되어
있습니다. 아래는 2·3단계를 무리 없이 얹기 위한 준비/설계입니다.

---

## 1단계 (완료): 보안운영 명세서 작성

- 입력: KISA 명세서 엑셀 + 기업 문서
- 처리: 점검항목 단위로 운영여부/운영현황/관련문서/운영증적/보완사항 작성
- 출력: 원본 양식 보존 + 결과 열 채운 엑셀
- 구현: `app/parsing/template.py`, `app/parsing/excel_writer.py`, `app/core/pipeline.py`

## 2단계 (계획): 사후 서면평가 증적자료 제출목록

KISA 양식에는 점검항목별로 제출해야 할 **증적자료 목록**이 정의됩니다(보통 별도 시트
또는 별도 엑셀). 목표는 다음과 같습니다.

- 증적 제출목록의 각 항목을, 명세서 점검항목 및 기업 문서와 **매핑**한다.
- 각 증적에 대해 "제출 문서에서 확인됨 / 일부 확인 / 미확보" 상태와 근거 파일을 표기한다.
- 미확보 증적은 **수집 체크리스트**로 출력한다.

준비 사항 / 설계 방향:
- `app/parsing/evidence_list.py` (예정): 증적목록 시트 파서. 명세서 파서와 동일한
  "헤더 키워드 감지 + forward-fill" 방식을 재사용.
- 1단계의 `ItemResult.related_docs` / `evidence` 결과를 증적 매핑의 입력으로 재사용.
- 프롬프트는 "이 증적이 제출 문서에 존재하는가?"를 판정하는 형태로 별도 작성.
- 산출물: 증적 제출목록 엑셀(상태/근거/담당 열 채움) + 미확보 항목 요약.

## 3단계 (계획): 신청양식 자동 초안

신청서·서비스 개요 등 서술형 양식의 초안을 기업 문서에서 추출/요약해 채운다.

준비 사항 / 설계 방향:
- `app/parsing/application_form.py` (예정): 양식의 입력 필드(라벨→셀) 매핑.
- 필드별로 "기업 문서에서 해당 정보 추출 → 양식 문체로 요약" 프롬프트 작성.
- 사람이 검토할 수 있도록 출처(근거 문서) 주석/코멘트를 셀에 부기.

---

## 공통 확장 포인트(현재 코드 기준)

- **새 산출물 = 새 parsing 모듈 + 새 prompt + pipeline 변형**. 문서 추출/청크/검색/
  LLM 호출은 그대로 재사용한다.
- 산출물을 **서비스 모듈**로 분리하기 위해, 차후 `app/services/{spec,evidence,application}.py`
  형태로 파이프라인을 묶고 웹 UI에 "작업 종류" 선택을 추가하는 것을 권장한다.
- 입력 문서 1회 업로드 → 여러 산출물 동시 생성(배치)으로 확장 가능.

## 기타 개선 백로그

- HWP(.hwp/.hwpx) 입력 지원(2단계와 함께 검토).
- 어휘 기반 검색 → 임베딩 기반 검색으로 정확도 향상.
- 작업 상태/결과 영속화(DB/스토리지), 다중 사용자, 인증.
- 점검항목별 근거를 셀 코멘트/하이퍼링크로 부기해 추적성 강화.
